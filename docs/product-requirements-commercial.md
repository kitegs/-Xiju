# Insight Studio 商业化产品需求基线

## 2026-09-07 增量：单机多表与交付收敛

- 数据准备新增字段口径：字段角色、中文名称、单位、币种、粒度、日期格式；修改产生新版本，历史报告保持原口径。
- 多表首发支持 1:1 / N:1 左连接或内连接，先验证匹配率、未匹配数、重复键，用户确认后生成副本；空键不得彼此匹配，N:N 拒绝，原件不变。
- 重复的右表数值显示粒度限制；再次关联和清洗改名不得解除限制，Artifact/Evidence 保留关联来源版本。
- 报告库每页 24 条摘要，服务端搜索、数据集筛选、排序和回收站；列表不传输图表数据和证据全文。
- 模型降级须可见，无效输出同样计 Token。自动规则得分不是业务质量；真实模型、浏览器和 DOCX 验收分别记录。
- 当前范围与未完成门槛以 [收敛计划](convergence-plan.md) 和 [多表验收](bike-sharing-multitable-acceptance.md) 为准，不扩大企业账号、Cube 或复杂多事实表范围。

## 2026-09-06 增量：收敛与修复闭环

当前发布范围收敛为单机数据分析与可复核报告，见 [收敛计划](convergence-plan.md)。报告核验面板增加“重算并预览修复”：基于原数据版本全量重算，显示变更和修复后质量，用户确认后保存历史版本。恢复列出的系统结论，不覆盖新增自定义段落、图表或排序；未被认证的文字保留待核验状态。预览后数据/报告变更时必须拒绝旧提案。

## 2026-09-05 增量：结论校验第一层

确定性生成报告保留服务端结论及证据基线；内容/引用变更后标为待核验。保存不代表认证，未通过不得标记可交付或通过正式 DOCX 导出。检查面板区分事实、解释、建议与未确认假设，支持定位正文；未保存时明确上次检查已失效。结构化比率、期间增长、排名可复算；自然语言同义改写、因果和预测真实性尚不自动认证。旧报告需重新生成基线，不自动背书。

## 2026-09-05 增量：报告管理

单机免登录报告库补齐手工创建、复制、重命名、查询筛选、软删除与恢复。已有编辑器承担正文/图表增删改和排序；离开未保存内容需确认。复制保留来源数据版本与证据，不共享后续编辑状态。删除不级联删除数据、Artifact 或 Evidence；已导出文件和外部发布副本不随之撤回。暂不提供永久清空。

## 2026-09-05 增量：可开关分析能力

输入框附近提供会话级菜单：需求澄清、深入分析（1–3 轮固定只读诊断）、内容审阅、图表排版、多方案结构比较。提供快速分析与完整报告预设，保存设置后刷新保持；已经生成的计划冻结原配置。关闭组件不得绕过权限、基础质量检查或现有报告的确认保存。

组件结果须展示完成/失败/未执行、操作内容、模型调用次数及返回的 Token。模型格式错误仍保留用量。无模型时说明本地执行，不冒充 AI 审阅。排版仅作用于新报告；多方案当前为规则生成的章节排序提案，不是多个完整 AI 报告。多表关联尚未实现，菜单保持禁用。

## 1. 产品决策

Insight Studio 不以复刻 Tableau、Power BI 或 Superset 为目标，也不把“AI 可以问数和画图”作为独立卖点。产品定位为：

> 面向专业个人、小公司和报告服务人员的本地优先 AI 分析报告工作台，将 Excel、CSV 和业务数据库中的数据转换为可验证、可编辑、可重复运行的专业报告。

产品交付的核心不是一段对话，而是一组可继续使用的资产：数据版本、清洗配方、正式计算结果、图表、报告、证据和可重跑流程。

### 1.1 核心价值承诺

1. 新用户无需掌握 SQL、Python 或传统 BI，也能在 15 分钟内生成第一份可编辑报告。
2. 报告中的正式数值由确定性工具计算，不由大模型估算。
3. 关键结论可以查看数据范围、指标定义、计算方法、代码和结果证据。
4. 用户替换下一期数据后，可以重放既有清洗和分析流程，更新整份报告。
5. 单机版不依赖账号、Superset 或外部数据库即可完成核心流程。

## 2. 目标用户与首发场景

| 优先级 | 用户 | 主要任务 | 产品收益 |
|---:|---|---|---|
| 1 | 小公司运营、财务、销售负责人 | 周报、月报、经营复盘 | 减少整理、计算、制图和写报告的重复劳动 |
| 2 | 咨询、代运营、财税与数据服务人员 | 为多个客户重复交付报告 | 模板化交付并降低人工错误 |
| 3 | 研究者、教师和问卷分析人员 | 统计分析与研究报告 | 提供方法检查、效应量、限制和可复现步骤 |
| 4 | 小团队分析师 | 协作、审核、分享与定时刷新 | 在个人版资产模型上增加团队治理 |

### 2.1 首发任务

- 上传一份 Excel 或 CSV，自动识别字段、类型和质量问题。
- 用自然语言提出经营、清洗、统计、图表或报告要求。
- 审阅 AI 生成的结构化计划及其权限、成本和数据范围。
- 在数据副本上执行清洗、SQL、Python 或统计工具。
- 查看每一步操作、代码、结果、失败原因和证据。
- 生成并人工修改图表、报告段落和建议。
- 套用用户 Word 模板，导出 DOCX、PDF 和数据附件。
- 替换下一期数据，自动匹配字段并重跑原有流程。

## 3. 发布范围

### C0：商业基础改造

目标：把当前功能原型转化为稳定、可复现的单机产品内核。

- 统一 Project、DatasetVersion、Recipe、Run、Artifact 和 Evidence 模型。
- 原始数据不可变，任何清洗均产生新版本。
- 统一任务状态、重试、取消、恢复和运行历史。
- 建立结构化 AI 计划、工具注册表和质量门禁。
- 建立 Global Superstore 黄金验收流程。
- 保持现有界面可用，通过兼容接口渐进迁移。

### C1：Windows 个人专业版

目标：无需账号和 Superset，完成“文件到正式报告”的闭环。

- Windows 安装、卸载、首次启动向导和环境诊断。
- 本地项目、备份、恢复和版本升级。
- 经营月报与科研/问卷两套场景包。
- 图表和报告的可视化编辑、自动保存与版本历史。
- DOCX、PDF、Excel 附件的可交付导出。
- 模型数据出站预览、费用预算和用户自带 API Key。

### C2：小团队私有部署版

目标：5～50 人团队安全共享数据、分析和报告。

- 企业身份接入、工作区、成员、角色和资源权限。
- PostgreSQL、对象存储和分布式任务队列。
- 报告评论、审核、发布、只读分享与有效期。
- 定时刷新、定时报告、失败通知和备份恢复。
- 模型费用、工具调用、数据访问和发布审计。
- Superset 作为可选专业看板发布端。

### C3：企业增强版

不属于当前开发承诺。只有在 C2 出现真实付费需求后，才评估高可用、多租户、KMS、SSO 深度集成、灾备和 Cube 企业语义治理。

## 4. 核心业务流程

```text
创建项目
  → 导入数据并建立不可变版本
  → 自动画像与质量检查
  → 用户提问或选择场景模板
  → 生成 AnalysisSpec 和执行计划
  → 权限、成本、字段和方法校验
  → 用户批准所需步骤
  → 在副本上执行确定性工具
  → 产生 Artifact 与 Evidence
  → 图表/报告质量检查
  → 用户编辑并确认
  → 导出、分享或发布
  → 保存为可重跑配方
```

## 6. 场景包要求

### 6.1 经营报告包

必须覆盖销售、利润、费用、客户、库存的常见聚合，同环比、贡献度、异常、目标差距和行动建议。建议必须包含发现、证据、优先级、风险和验证方式，不输出无法由数据支持的确定性因果结论。数据缺少可靠日期、目标值或业务口径时，报告必须显式披露限制，不得补造趋势、目标差距或因果解释。

### 6.2 科研与问卷包

必须覆盖描述统计、置信区间、Cronbach α、t 检验、ANOVA、卡方、回归、效应量、多重比较和样本量提示。每次检验必须披露适用前提、缺失处理、样本量、统计量、p 值、效应量、区间和限制。

## 7. 非功能需求

| 领域 | 商业 Beta 门槛 |
|---|---|
| 正确性 | 黄金案例正式数值一致率 100%；关键结论证据覆盖率 100% |
| 性能 | 10 万行常用文件可交互分析；大操作进入后台任务且界面不假死 |
| 可靠性 | 强制退出后项目可恢复；重试不产生重复成果 |
| 安全 | 密钥不进浏览器、日志和项目包；原始数据默认只读 |
| 隐私 | 外部模型调用前可见数据边界；支持关闭联网模型 |
| 可用性 | 新用户在引导下 15 分钟内生成第一份报告 |
| 可维护性 | API、领域逻辑、存储、工具和前端功能模块分离 |
| 兼容性 | 旧项目通过迁移器打开；迁移失败不得原地破坏旧数据 |

## 8. 商业验证指标

商业 Beta 应以真实使用而不是功能数量验收：

- 10 名目标用户中至少 6 名无需现场指导完成第一份报告。
- 用户完成第一份可用报告的中位时间不超过 15 分钟。
- 替换下一期数据并重跑报告不超过 5 分钟。
- 关键正式数值错误为 0。
- 至少 7 名测试用户愿意再次使用。
- 至少 3 名测试用户愿意付费试用或签署明确购买意向。

未达到上述门槛时，优先改进流程、模板、证据和引导，不横向扩张功能。

## 9. 明确不做

C0～C1 不承诺：

- 完整复刻 Tableau 的全部菜单和图表；
- 让 Superset 成为个人用户的必需入口；
- 公网多租户 SaaS；
- 大型企业高可用与多地域容灾；
- 任意生成代码在宿主机直接运行；
- 自研通用数据库连接器生态；
- 同时覆盖大量行业模板；
- 依赖模型输出未经工具验证的正式数值。

## 10. 发布门禁

版本只有同时满足以下条件才能标记为商业 Beta：

1. Global Superstore 黄金流程端到端通过。
2. 经营报告和科研报告各有一套数值黄金样例。
3. 数据版本、清洗配方、运行和证据可以完整重放。
4. DOCX/PDF 导出通过确定性质量门禁、数值断言和逐页视觉检查；错误级问题不得人工忽略后直接发布。
5. 安装、升级、备份、恢复和诊断完成演练。
6. 开源许可、隐私说明、用户协议和数据出站说明齐备。
7. 未实现功能不以可点击假入口出现在正式界面。
