# 报告结论质量第一阶段实施计划

目标：给确定性生成结论建立服务端校验基线，改写后未核验的结论不得继续通过交付门禁。
方案：复用 ReportDocument/Evidence；独立 report_claims 模块生成并检查文本、引用与证据指纹。只认证确定性生成链路的原始结论，不以数字在证据中出现证明语义正确。任何未认证改写标记待核验。规则计算与测试另外验证增长、单位换算和排名。
约束：单机免登录，不下载依赖、不调用付费模型、不改原数据；保留已有报告版本。校验基线只由服务器生成，PUT 不接受客户端替换。

- [x] backend/tests/test_report_claims.py：先写数字替换、引用交换、证据篡改、未知结论、增长与单位测试，运行应失败。
- [x] backend/app/report_claims.py：seal_claims(document) 建立基线，check_claims(document) 返回定位信息；增长计算禁止零/负基期，期间类型显式区分。
- [x] services.py / schemas.py：生成时封存；质量检查输出 claim_checks，非认证事实阻止通过。
- [x] main.py：保存时保留服务端基线和证据，阻止客户端伪造质量认证；草稿仍可保存。
- [x] App.vue / ReportClaimChecks.vue：显示校验状态、结论分类、具体对象与证据，点击定位正文。
- [x] 固定合成零售基准，明确不是原始 Global Superstore；全量后端、前端构建及浏览器回归。

自由自然语言推理的正确性、因果识别和外部数据真实性不属于本轮可证明范围。旧报告无基线时提示重新生成，不自动认证。

验收：6 项新增专项测试（其中一项包含保存/导出接口防伪），合成 Superstore 报告金额与排名断言；浏览器 4 条流程和构建通过。第一层完成，通用语义理解与自动补算认证留给下一阶段。
