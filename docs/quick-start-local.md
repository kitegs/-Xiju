# 单机首次使用：从示例到可编辑报告

无需账号，Superset、Cube、Docker 均不是普通报告功能的前置条件。当前是 Alpha；规则通过不等于业务结论已获人工确认。

## 1. 启动前检查

在项目目录运行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/check-local-readiness.ps1
```

检查 Python 3.10+、Node 20+、npm 和本地依赖，不会联网或安装。缺少依赖时，先确认允许下载，再在所选 Python 环境安装 `backend/requirements.txt`，在 `frontend` 按 `package-lock.json` 安装依赖。不要把 `D:\PY` 当作每台电脑必备路径。

双击 `start.bat`，打开它显示的 Web 地址。端口可能变化，不要照抄旧书签。保留 API/Web 窗口；关闭窗口会停止服务。启动失败先看窗口错误。8010 被其他服务占用时，启动器可能跳过后端启动，须先确认端口归属，不能直接结束陌生进程。

## 2. 先体验，再启用真实模型

1. 不配置模型也可点击“载入示例”，试用本地固定分析；这不是 DeepSeek 生成，Token 为零。
2. 打开设置 → 模型与 API → DeepSeek，填写自己账户可用的模型 ID、API 地址和 Key，启用并设为默认，点击“保存设置”。
3. “测试连接”会真实发送请求，可能消耗 Token。返回页面后再次确认配置已保存；刷新后密钥框为空是正常保护行为，不代表密钥丢失。
4. 模型配置成功不等于所有分析都成功。使用设置 → Token 中心查看阶段用量；服务商没有返回 usage 时应显示未知，不应当作零。

## 3. 生成与检查

选择数据，输入：“给管理者生成简要报告，保留关键指标、主要发现和限制，不做预测。”

- 输入框附近设置权限、分析能力和报告要求；先用安全模式，SQL 需要审批。
- 若出现澄清问题，可填写，或使用推荐默认值；报告会保留“未经确认的业务假设”。
- 检查计划后运行；规划/分析中均可取消。取消不回滚已经完成的操作，也不能保证服务商立即停止计费。
- 对话中展开“查看实际执行记录”→ 某一步 → 输入、输出、代码、证据、事件时间线。计划只是拟执行步骤，实际记录才说明是否成功。
- 运行显示失败、降级、结果截断时，先查看原因；“已结束”不是“完整交付”。本轮新增的失败/降级门槛只自动应用于新生成报告，历史报告不会被静默改写。

## 4. 修改、保存、恢复

点击“可编辑分析报告已生成”打开编辑器。可修改标题和文字、右键编辑图表，在对象树上移/下移排序，再点击“保存”。修改数字后必须重新核对证据。

AI 修改已有报告仍采用：变更方案 → 差异和质量检查 → 确认保存，不直接覆盖。报告库可搜索、复制、重命名、批量移入回收站并恢复。

## 5. 常见问题

- **没消耗 Token**：可能没有启用模型，或只有本地计算；查看每阶段记录，不只看聊天是否有文字。
- **数值正确但回答不贴题**：当前专题分析仍有模板残留，请保留问题、Run ID 和报告版本反馈；不要只重新生成到满意为止。
- **重启后中断**：运行历史中的 interrupted 可重试；点击同一轮重试不会重复创建规划任务。队列会在启动后恢复。
- **想用 Superset**：它是可选专业工具，需要另外配置；先完成本地报告闭环再接入。
- **备份/开源发布**：`data/` 有原始数据、数据库和本地密钥，备份需妥善保管，绝不能上传公开仓库。

验收边界：已安装依赖的机器上使用全新测试数据目录，自动验证免登录、配置保存、示例分析和报告编辑；尚未在干净 Windows 虚拟机执行从零安装，也尚未由真正的陌生用户做可用性测试。
