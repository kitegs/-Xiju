# 对话操作与需求响应边界（2026-09-08）

## 需求是否影响成稿

当前不是通用自由报告 Agent。用户目标能影响规划、SQL、能力选择及总结；基础报告仍由 build_report 的确定性字段规则构建，prompt 主要保存为元数据，未驱动章节规格。中间层不是天然问题，问题是语义在边界丢失：用户目标 → 工具结果 → 正文选材尚未完整贯通。因此不同提示词可能得到相同的基础图表和相似正文。本次没有宣称修复报告个性化。

后续验证应固定同一数据版本，分别要求：只分析亏损、不生成趋势；给管理层三条结论；详细讲方法和限制；只比较工作日小时需求。逐项断言主题覆盖、禁止项、证据选择和章节不同；不以文字随机变化衡量个性化。保留安全层、数值复算和审批，不用删除中间层换取自由度。

## 查看操作

截图中的列表是计划。现在计划下方和最终回复均可展开“查看实际执行记录”。新 Run 的 step.completed 事件保存执行状态、输入/输出摘要、代码以及关联证据预览；展开后运行中自动刷新，取消/失败后也保留已完成步骤。事件时间线显示开始、结果、取消等事件。执行代码与证据代码可展开，结果数据是已保存预览，不代表完整源表。

旧 Run 不会伪造明细；旧回复已有 tool_runs 时仍可查看。工具失败不再统一显示为完成勾号。这里展示工具轨迹、方法与结果，不是模型隐藏推理。较长工具输出仍受原执行器摘要限制，未实现通用无限日志或 Python 逐行实时终端。

## 中断

对话消息区底部新增“停止当前对话任务”。运行阶段调用既有后端取消接口；请求中断不回滚已完成副作用，也不能保证线程中的本地计算瞬时终止。规划阶段使用 AbortController 停止等待，并阻止客户端自动执行计划；规划尚未持久化为可取消 Run，服务端请求可能继续完成与计费。这是已明确的限制，不称为完整上游硬取消。

## 批量管理

- 报告卡片勾选、全选本页、清空选择、批量移入回收站和恢复；搜索/换页重置选择，防止误删不可见项。
- 会话列表勾选、全选当前列表、清空选择、批量移入回收站和恢复。会话 DELETE 改为 archived，不删 ChatMessage/Run/报告/数据。
- 执行前显示数量并确认，逐项请求，报告部分成功和失败；运行中会话拒绝归档，须先取消。
- 范围是报告库与会话列表，不包括单条消息或报告内内容块的多选。
- 单机免登录保持不变；本轮未升级团队权限体系。

## 使用与升级

后端变更需重启本地 API，前端刷新。没有安装依赖或调用真实 DeepSeek。本轮不删除任何用户真实会话或报告；删除测试仅在隔离数据库执行。

验证：后端全量 98 passed（仅 pytest 缓存目录权限警告），浏览器 10 passed，前端生产构建通过。浏览器新增批量报告回收/单项恢复、会话回收/恢复、规划中断不自动运行测试。中断执行器的覆盖沿用既有后端测试；没有新增真实模型或远程 MCP 的硬取消验收。
