# 报告需求与执行协议首轮验收

## 本轮实现

单机免登录保持不变。用户决定报告要求、能力范围和权限，模型在服务端工具策略内选择工具。原始文件保护、外部发布审批、报告变更预览后确认的边界不变。

1. 总结使用 synthesis-v4 具名事实协议。模型选择 fact_id，事实原文由服务端从证据目录填充；未知或冲突引用被拒绝。解释与建议单独呈现为待验证内容，未通过的文字明确记录，旧版已保存内容保持可读。
2. 对话新增报告要求面板，提供自动、简报、标准、详细，以及综合、亏损、小时需求主题。要求进入计划与报告快照；自定义包含和排除要求标为待核验，不宣称任意自然语言要求均已满足。
3. 亏损专题实际计算负利润记录的亏损绝对额、记录数及分组。补算使用明确的参数 Schema，并停止同内容维度换名后的重复分解。详细综合报告可展示补充 SQL 结果。解释与行动效果仍须业务验证。
4. 规划新增持久化 Run，前端通过异步接口等待结果，停止按钮可以取消规划任务。规划 worker 本身不执行工具；执行仍走独立 Run 与审批。报告修复重用保存的要求，不覆盖手工新增内容。DOCX 简报省略附录，其他导出仅展示正文引用的证据，完整证据仍保存在报告数据中。
5. 新增同数据不同要求、事实引用拒绝、报告修复、异步规划完成及排队取消测试；保留批量回收恢复和报告编辑等浏览器回归。

## 验收结果

- 隔离数据库后端完整回归：105 项通过；随后针对导出中发现的问题补充断言并重跑。
- 浏览器回归：10 项通过，包括对话中断、批量回收恢复、报告重算修复及多表流程。
- 前端生产构建通过；最大输出分包约 404 KB。
- 通过项目实际导出器生成可手算的三行数据样本：销售额 600、净利润 10、亏损绝对额 30、亏损记录数 2。未使用用户原始文件或付费模型。
- Word 后台转 PDF 后逐页检查：简报 1 页、详细版 5 页、亏损专题 3 页。修正了空白分页、图注与来源跨页，以及低基数 Profit 被自动当成维度的问题。最终样本无空白页、明显裁切或重叠；详细版的留白和模板式解释仍有优化空间。
- 标准渲染环境缺少 LibreOffice，文档运行时也不含项目导出器依赖的 matplotlib；采用项目既有运行环境导出、本机 Word 后台转换、文档运行时栅格化，没有下载依赖。

## 不能据此宣称的能力

- 未运行新版协议的真实 DeepSeek 联网稳定性验收。本轮模型 Token 消耗为零；mock 通过不等于真实模型质量通过。
- 当前是有限预设的差异化编排，不是任意行业、任意写作要求的自动交付系统。自由文本要求仍需逐项核验。
- “不要趋势”控制报告正文与导出呈现；通用固定计算仍可能产生内部趋势证据，并不保证不执行相关计算。
- 补算仍在固定算子范围内，不能证明因果，不能保证每次都发现有商业价值的新结论。对话解释不等于经过审阅的整篇商业论证。
- 取消不能退回上游已消耗 Token，也不能保证外部服务立即停止。需继续补模型、Python、MCP 运行中取消及重启恢复的端到端故障注入测试。
- 规划重试会创建新的规划任务；重复点击的跨请求幂等去重仍需增强。

## 后续验收顺序

先使用 Global Superstore 和 Bike Sharing 做真实 DeepSeek 的同数据不同需求对照，分别记录规划、补算、总结协议的成功率与 Token。再评审内容是否切中需求，而不仅检查数字一致。之后补充自定义要求覆盖评估和更细的版式预设，不新增模型权限。
