## 真正需要修的边界

### P0：总结引用必须理解“引用了什么”

五次总结被未绑定数字规则拒绝。仅强化提示词不足：Superstore 第一次原始响应将 `risk_count` 指向 `discount-profit.calculation.facts.1.value`，而该项是样本数，并非风险记录数。此次整段被其他校验拒绝，但不能依赖偶然格式错误兜底。

下一步将任意位置 path 改为具名事实契约：fact_id、metric、role、unit、dimension/member、period、value；服务端校验角色和单位，再渲染数字。禁止把合法路径等同于合法结论。按 Claim 独立拒绝并显示部分完成；不得静默纠正业务含义。数值格式（精度、百分比、单位）由服务端统一。固定保留“把样本数当风险数”的负例。

### P0：计划参数与真实工具契约对齐

固定诊断一次只接收一个 dimension/measure。数组不是合法替代，不能偷偷取首项。把工具 JSON Schema 与合法候选显式发给模型；多任务用结构化步骤数组，并受轮数预算约束。使用保存的失败响应做离线负例，之后再做有预算的真实回归。

### P1：SQL 保守限制与口径工具

Bike 第二次在 DISTINCT 日键子查询后的聚合也被当前规则拦截；这是保守限制，并非该 SQL 一定重复累计。优先提供确定性的日级核对工具，让模型不必绕过防护；后续再评估基于 SQL AST 的粒度证明，不删除防重累计规则。

### P1：解释和排版

- Superstore 缺少日期，行动仍建议“增长与稳定性”；应先要求恢复日期，并优先给出可计算的区域利润率、亏损额分解。
- Market 与 Market2 产生重复补算；需按字段内容/已完成问题去重，补算应带来信息增量。
- Bike 新的观测均量章节与旧分组/深度分析重复，尚未形成精炼故事线；“币种”等零售措辞仍有残留。
- 建议需要明确执行对象、前提和验收指标，不把未经验证的原因写成结论。
- 总结阶段约占主批次 Token 的 44.8%，应发送精选具名事实而非冗长证据集合。
