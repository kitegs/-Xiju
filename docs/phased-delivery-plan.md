# Insight Studio 分阶段完善方案

> 本文为历史实施记录，不能据此判断当前缺失功能。2026-09-06 后的优先级以 [单机主线收敛](convergence-plan.md) 为准。

版本：1.0（2026-08-13）

## 0. 2026-08-14 阶段 0～3 实施结果

本轮已完成可运行的个人专业版纵向闭环：全量读取与增强质量检查、DeepSeek 结构化计划、DuckDB 副本 SQL、可选 Docker Python 沙箱、证据与费用追踪、独立图表工作台、ReportDocument 2.0、分页报告编辑、撤销/重做、版本恢复、PDF 打印和 DOCX 导出。

Global Superstore 验收结果：51,290 行完整读取；坏日期字段被识别；DeepSeek 生成两条受控 SQL 并完成 6 步计划；报告生成 6 个基础图表和完整证据链。仍未进入本轮范围的能力包括：Superset 正式部署、服务端 PDF、多人认证/RBAC、协同批注、Cube 指标治理和生产级任务队列。

## 0.1 2026-08-16 阶段 4 实施结果

已完成适合本机/可信局域网试运行的小团队纵向闭环：工作区成员、Owner/Admin/Analyst/Viewer 角色、后端权限检查、报告对象批注、草稿/审核/批准/发布状态机、限时只读分享和操作审计。Superset 可使用本机已有固定镜像独立启动，平台实时检查健康状态，并仅由后端服务账号换取短期 Guest Token。Cube、企业 SSO、PostgreSQL/Alembic、对象存储、异步任务和生产备份归入下一阶段，不能将当前本地身份回退机制视为公网认证。

## 0.2 2026-08-16 阶段 4.1 实施结果

对话顶部新增智能自动、快速探索、深度分析、数据清洗、商务报告、科研统计、问卷分析和专业看板八种模式。模式会约束计划工具而不只是改变提示词；科研模式计算均值、中位数、样本标准差和 95% 置信区间，问卷模式识别候选量表并计算 Cronbach α，清洗模式只生成可重放建议而不修改原文件。

Superset 已从“空看板初始化”升级为真实发布闭环：专业页显示三步向导和发布预览；后端创建隔离 MySQL 数据副本、注册 Database/Dataset、把 ChartSpec 映射为 Superset Chart、更新 Dashboard 布局、启用 Embedded Dashboard，并保存资源映射和审计。Global Superstore 验收为 51,290 行、1 个 Dataset、6 个 Chart；重复发布复用同一组资源。当前本机 MySQL 仅是无需下载的阶段验证组件，不替代正式版 PostgreSQL/仓库设计。

## 0.3 2026-08-17 阶段 4.2 实施结果

对话输入区增加预测、行动建议、生成报告和 Word 模板选项。预测会先显示受控计划，随后在副本上执行候选基线回测，保留 MAE、RMSE、MAPE、预测区间、参数和可复现代码；建议以“发现、建议、优先级、风险、验证方法、证据引用”对象呈现。执行详情可展开输入、输出、耗时、数据版本和 SQL/Python/方法代码。

## 0.4 2026-08-18 阶段 4.3 实施结果

Lite/单机仍默认本机可信所有者，不要求创建账号；这不移除能力级安全边界：外部发布仍需计划批准，任意 Python 仍只允许隔离沙箱，Superset 管理凭据仅在后端。科研模式现在对可用字段自动运行 Pearson/单变量 OLS、Welch t 检验、单因素 ANOVA 与 Bonferroni 校正事后比较、卡方独立性检验，并给出 Cohen's d、η²、Cramér's V 和规划用样本量提示。问卷模式增加分组/量表交叉分析；所有统计均保存方法、适用限制、字段和可复现代码。

预测由单一留出集选择改为最多三折的滚动时间回测，输出平均 MAE/RMSE/MAPE、异常周期（MAD robust-z）、趋势斜率、季节期、残差标准差和区间警告。`AnalysisRun` 本地持久化队列提供排队、运行、已完成、失败、取消状态，步骤进度、错误、结果消息和报告 ID；API 支持列表、取消、重试，前端在对话和运行历史显示状态。Superset 专业页以 MessageChannel 按官方嵌入协议获取后端签发的短时 Guest Token 并定时刷新，保留“完整编辑器”回退入口。生产版仍应替换为 Redis/Celery/RQ 或同类持久化 Worker，并做跨进程取消、死信、调度和监控。

新增 Word 模板中心：用户可上传带 `{{ report.title }}`、`{{ report.summary }}`、`{{ metric.sales }}`、`{{ recommendations }}`、`{{ chart.<chart_id> }}` 的 DOCX 模板，预览识别出的占位符并生成独立 DOCX。上传会拒绝 DOCM、宏、嵌入对象、外部关系、压缩炸弹和不安全内部路径；模板上传属于 `template.manage`，填充导出属于 `template.use`，不等同于报告正式发布。

## 1. 结论

V2 当前已经形成“示例/上传 → 对话 → 确定性分析 → 可编辑报告”的可演示链路，但还不是可交付给小公司的正式产品。接下来不应优先堆更多图表，而应按“单人闭环、专业编辑、团队治理、语义治理”四道门推进。

Cube 与 Superset可以接入，但承担不同职责：Cube 是正式业务指标与权限的语义层；Superset 是专业仪表盘工作台；Insight Studio 保留小白对话入口、分析编排、报告编辑和审核。临时 CSV/科研小数据继续走本地引擎，不强制进入 Cube。

## 2. 当前能力与关键缺口

| 领域 | 当前状态 | 距正式版的主要缺口 |
|---|---|---|
| AI 对话 | 会话、上下文、报告工件、本地回退可用 | 流式响应、计划确认、工具过程、引用展开、失败恢复 |
| 数据 | CSV/Excel 上传、示例、基础画像 | 数据预览、字段类型修正、清洗配方、撤销、版本 |
| 图表 | 基础 ChartSpec、字段/聚合修改 | 筛选、排序、格式、配色、标签、联动、质量规则 |
| 报告 | 页面式编辑、对象树、保存、打印 | DOCX/PDF 服务端导出、分页、表格、模板、版本与批注 |
| 设置 | 五类设置可切换，模型/偏好可保存 | 配额、模型调用审计、KMS、管理员策略、健康诊断 |
| 团队 | 工作区数据模型雏形 | 登录、成员、RBAC、资源权限、分享、审计、备份 |
| Cube/Superset | 配置和状态占位 | Token 代理、Meta 同步、Guest Token、映射、RLS、一致性测试 |

## 3. 阶段路线

### P0：稳定可演示版（当前冲刺，1～2 周）

目标：任何新用户在 10 分钟内稳定得到并修改第一份报告。

- 修复所有死按钮、空白页、启动失败与无反馈操作；
- 一键启动增加 API/Web 就绪检查和可读错误；
- 示例数据、推荐问题、模型配置、设置保存形成验收脚本；
- 把 `App.vue` 拆为对话、数据、报告、设置模块，避免继续形成单文件巨石；
- 增加前端组件测试与一条端到端冒烟测试；
- 明确未实现功能，禁止用可点击假按钮伪装可用。

退出标准：冷启动成功率 100%；核心路径没有死按钮；API 不可用时页面可诊断并重试；构建和测试通过。

### P1：个人专业版（4～6 周）

目标：个人用户可对真实小数据完成清洗、分析、精修和正式文件交付。

- 数据表格预览、字段类型/日期修正、缺失/重复/异常检查；
- 结构化清洗配方，支持预览差异、撤销、重放和数据版本；
- AI 展示分析计划、工具调用、证据和失败原因；高风险步骤需确认；
- 图表属性补齐筛选、排序、Top N、颜色、数字格式、标签和注释；
- 报告编辑器补齐表格、分页、模板、撤销/重做和自动保存；
- 后端生成 DOCX/PDF，并做中文字体、分页和图表视觉回归；
- 商务、科研、问卷三套报告模板与质量门禁。

退出标准：10 万行以内典型文件满足性能基线；报告数值证据覆盖率 100%；DOCX/PDF 可交付；全链路可复现。

当前进度：数据表预览、质量摘要、七类清洗步骤、影响预览、新版本/配方记录、步骤排序、编辑撤销/重做、历史配方载入与重放已经落地；AI 对话也已支持计划审批、工具执行过程和证据展开。下一批优先做字段类型人工修正建议、数据版本树与结果版本回退，以及更大文件的 DuckDB/Polars 分页路径。

### P2：小团队正式版（6～10 周）

目标：5～50 人团队可安全协作并正式发布报告。

- 身份认证、成员邀请、Owner/Admin/Analyst/Viewer；
- 数据集、会话、报告、连接的资源级权限；
- PostgreSQL、对象存储、Redis Worker 与 Alembic 迁移；
- 报告版本、批注、审核、发布、只读分享与有效期；
- 数据刷新、定时报告、失败重试和通知；
- 操作审计、模型调用成本/配额、备份恢复演练；
- Superset Embedded SDK、后端 Guest Token、资源映射和 RLS。

退出标准：越权测试全部通过；50 并发只读用户核心 API 错误率低于 1%；备份可恢复；Superset 不需要二次登录且不能越权。

### P3：Cube 语义层正式版（6～8 周，可与 P2 后半并行）

目标：AI、报告和 Superset 使用同一套正式指标口径。

- 选择一个业务域建立 Cube 模型、指标、维度、Join 和时间粒度；
- 同步 Meta API，建立指标目录、同义词、单位、负责人和状态；
- FastAPI 作为短期令牌代理，浏览器不持有 Cube 密钥；
- 认证指标/草稿指标审核流，禁止同名指标重复定义；
- Superset 通过 Cube SQL API 查询治理数据；
- 行级权限、预聚合、刷新状态和变更影响检查；
- AI 与 Superset 指标一致性黄金测试。

退出标准：选定业务域的一致性测试 100% 通过；权限覆盖 REST/SQL/Meta；核心看板 P95 小于 2 秒。

## 4. 当前优先实施顺序

1. 前端模块化与错误边界；
2. 数据预览和清洗配方；
3. AI 计划/工具/证据可视化；
4. 图表属性与报告 DOCX/PDF；
5. 身份/RBAC/迁移/审计；
6. Superset 嵌入；
7. Cube 单业务域试点，再扩展公司指标。

## 5. 不建议现在做

- 不把 Superset 或 Cube 源码直接复制进 V2；使用固定版本服务和适配层；
- 不让 AI 通过浏览器点击 Superset 生成图表；使用 API 和结构化映射；
- 不为临时文件强制建 Cube 模型；
- 不在 RBAC 完成前开放团队邀请或公网分享；
- 不先做“更多图表类型”而跳过证据、清洗、导出和版本能力。

## 6. 每阶段统一质量门禁

- 新功能必须有需求编号、接口契约、自动化测试和用户可见错误；
- 所有数字结论必须引用证据，模型不得直接计算正式指标；
- 密钥不回传、不进日志、不进 Git；外部请求必须可知、可控、可审计；
- 页面不允许无事件的假按钮；规划功能使用只读状态和里程碑说明；
- 每个发布候选执行示例数据端到端、恶意文件、越权、导出视觉和恢复测试。
